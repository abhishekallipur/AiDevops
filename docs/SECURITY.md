# Security

Updated 2026-11-25. Local single-user application. Docker and AWS management routes require the configured administrator session; other project APIs retain their existing access model. There is no general rate limiting. Bind API/UI to loopback and never expose this service to untrusted networks.

Repository/archive contents and model responses are untrusted. Static analysis executes no code, skips known sensitive paths and symlinks, and applies file/depth/read bounds. Archives reject traversal, absolute paths, links and oversized content. Rejection can leave partial extracted data; multipart spooling occurs before endpoint reads, so bounded UploadFile.read is not a complete ingress quota. Malformed archive normalization and cleanup remain open.

Planning uses schema validation, labelled mock fallback and bounded provider retries. SDK retries are disabled to avoid multiplying configured attempts. Proposed commands are advisory. Artifact values are sanitized and statically scanned for secrets; diagnostics redact matching values. These checks are heuristic, not proof of a safe or buildable configuration.

Execution is registry-only. Human API approval is required; image builds require a tool approval too. Docker tests use filtered temporary source snapshots, read-only mounts and writable in-container copies. Known credential paths, VCS/caches and symlinks are omitted; no host environment credentials or Docker socket are passed through. A 1 GiB memory limit, 2 CPU limit, 256 PID limit, dropped capabilities and no-new-privileges apply to runtime test containers. Source changes during snapshotting and secrets with unusual names remain risks; only run trusted/approved projects. Test/dependency network access can exfiltrate any data present in the snapshot. It is not restricted to package hosts.

Subprocess output capture retains bounded memory, deadlines are capped by global/tool limits, and timed-out test containers receive a named force-removal attempt. Docker daemon failure can defeat cleanup. These runtime controls do not establish equivalent isolation/resource bounds for docker build. Building uses a generated-only context and remains PARTIAL; normal execute_job does not invoke it.

Atomic SQLite transitions reject duplicate phase entry; stale-state saves cannot overwrite cancellation. Cancellation does not interrupt the current subprocess and restart does not reconcile active jobs. Same-state concurrent saves lack revision checks. Local paths default enabled and are operator-selected rather than constrained by an enforced allowlist of roots.

.env and data/ are ignored. Do not print secrets or persist provider responses/errors containing them. Secret scanning uses a denylist/regex and cannot guarantee absence. Arbitrary test output can itself contain sensitive data and is persisted; generic output redaction is not implemented. No dependency-vulnerability/SAST scan was run.

No production/cloud/destructive operations were performed. Future infrastructure, permission or destructive actions must have explicit approval and independent verification.

## AWS deployment and monitoring — 2026-11-25

AWS management is a separate typed SDK service, not an arbitrary command or Terraform runner. It defaults to LocalStack with dummy credentials and does not fall back to AWS. Real AWS access requires the operator to set `AIDEVOPS_AWS_MODE=aws`; credentials are resolved only by the backend AWS SDK chain, optionally selected with the non-secret `AWS_PROFILE` name. The AWS setup page never accepts access keys; configure an SSO profile or role on the backend host. Endpoints require the configured administrator session. Credentials, instance user data, and arbitrary resource metadata are not returned to Streamlit.

The post-build deploy endpoint requires `approved=true` and an independent `public_access_confirmed=true`. S3 deployments create a new public static website bucket with only `s3:GetObject` allowed; EC2 deployments publish the verified image to ECR, create a security group permitting public TCP/80, and launch one configured `t3.micro` instance. Both paths can incur charges and expose the app publicly. Do not deploy private content. EC2 uses the configured instance profile; grant only the permissions needed to pull the deployment image. The LocalStack account ID is an emulator identity, not proof of an AWS account.

Static image extraction is label-verified, network-disabled, read-only, capped at 5,000 files/100 MiB, and rejects links/path traversal. Deployment records and operator outcomes are stored in a separate SQLite audit database. Failed deployments attempt cleanup of resources created by that operation; cloud permission failures can prevent cleanup, which is surfaced for review. Successful deployments currently have no Aidevops stop/delete operation. CloudWatch polling is read-only and capped at ten EC2 metrics per dashboard refresh. LocalStack was not running during implementation; mocked tests do not establish real AWS/LocalStack compatibility or production readiness.

## Privacy and local previews — 2026-10-23

Final AI egress filtering now covers both planner and legacy generator. Known credential URLs, tokens/private keys, assignment patterns and absolute paths are redacted; incomplete private keys block. HTTPS provider hosts default api.openai.com/openrouter.ai; AIDEVOPS_AI_ALLOWED_HOSTS extends the trusted list. AIDEVOPS_LOCAL_ONLY disables both external AI paths. Unknown secret formats and malicious metadata can evade heuristics. The prompt preview is after analysis, not permission-before-send. Prior source filtering/output scanning alone were insufficient; the new filter is an additional boundary, not proof of zero disclosure.

Build snapshots exclude known secret paths/symlinks/caches and block recognizable secrets in ordinary source. Approval identifies a hashed source+artifact copy. Builds execute generated Dockerfile instructions with network and Docker builder privileges; runtime CPU/memory limits do not constrain the builder equally. Use trusted projects. Raw source is not uploaded to AI by this workflow. Build output is bounded and heuristically redacted; runtime output is not exported to avoid arbitrary secret echoes.

Preview run uses label-checked image IDs, random loopback port bindings, no host source/socket mount, 1GiB/2CPU/256PID limits, dropped capabilities and no-new-privileges. Runtime values are not sent to AI or saved in review records; they use a short-lived env file removed after startup/on restart. POSIX0600 is requested; Windows uses inherited ACLs, so use a dedicated OS user/secured data directory. Docker administrators can inspect environment values until container removal. This is local trust, not an encrypted secrets vault.

Stop/cleanup verify ownership labels. Daemon unavailability yields visible error instead of verified removal. Build cancellation kills the Docker client; daemon-side work may require Docker inspection if interrupted. Restart never replays approvals. Expiry requires the backend; an app may remain running through an outage until reconciliation. No authentication was added: bind API/UI to loopback and do not expose to untrusted networks. New preview worker data supports one API process, enforced by OS lock.

## Application-aware packaging — 2026-10-23

Frontend and Python strategy inference is static; package scripts/Python source are never executed during analysis. Builds still execute untrusted dependency/build scripts only after snapshot approval. Frontend serving runs Nginx as USER101 on8080 with writable state only under/tmp; capability restrictions remain unchanged. Existing Dockerfiles are preserved for explicit review, so they retain their own build behavior; source snapshot secret/path filtering still applies. Live build output is bounded and heuristically redacted, not a guarantee against every arbitrary secret string. No private source was sent to external AI during actual todo verification.
